# Gaps between the schemas and the code

The schemas describe SyberWork as it behaves. They are not enforced at runtime except where `prepare_contract` and URL checks now match them. These are the places where a tighter reading would be wrong, or where the protocol name and the stored JSON differ.

1. **EffectOutcome.state is not stored.** `Work.commit` returns `status` with `succeeded`, `rejected`, or `unknown`. `effect_rejected` events reuse `status` for an HTTP code (409, 412, or 428). `effect_succeeded` and `effect_unknown` have no status field; the event kind is the state. `spec/validate.py` projects those events onto `state` only while checking the schema.

2. **AdmissionDecision is the `{status, reason}` object.** The `decision` event body also stores `proposal_id`, `policy_version`, and, on a failed commit recheck, `phase: "commit"`. Replay compares status and reason only.

3. **`install_contract` checks the fields admission indexes, including input kinds.** An acceptance `effect` without `action`, a `signoff` without `role`, a `fact` without `key`, or a `required_facts` item without `key` and `source` is rejected at publish. An input kind other than `string` or `integer` is `invalid_contract`. `create_case` rejects a value of the wrong kind with `input_schema`, including a boolean passed where an integer is required.

4. **`trusted_origin` is procedural.** Source install and `SYBERWORK_PLANNER_URL` now call it. The public errors stay `invalid_source` and `planner_unconfigured`. A host that only begins with `http://127.0.0.1:` is rejected. HTTPS rejects non-public addresses, `localhost`, metadata hostnames, and the suffixes `.local`, `.localhost`, `.internal`, and `.localdomain`. `SYBERWORK_HTTPS_HOSTS`, when set, is an extra hostname allowlist. The schemas still do not encode the parser (no userinfo, no fragment, path required, HTTP only for `127.0.0.1` with a port). DNS rebinding is checked at request time by `guard_request`, not at install.

5. **Proposals are appended before admission.** A non-dict `args` or a missing role list is stored, then denied with `invalid_proposal_shape`. The Proposal schema therefore does not require `args` to be an object.

6. **Amount checks use `type()` and `math.isfinite`.** `True` is not an amount (`amount_required`). `NaN` and infinities are not finite, so they are `amount_required` rather than compared to the limit. Negative numbers fail as `amount_exceeds_limit`.

7. **Acceptance clause ids must be unique in code.** The clause schema cannot say that by itself.

8. **`compiled_path` is optional on input.** Install writes the compiled path into the stored document. Examples already include one.

9. **Inspect projects resolution status.** `open`, `overdue`, `escalated`, `completed`, and `cancelled` are computed. The stored `resolution_requested` body has no status field. `ResolutionTask` describes the stored body.

10. **A legacy `reconciled` body may carry `evidence` and no `proof`.** `verified_reconciliation` does not treat it as success. The schema allows that historical shape.

11. **Contracts, policies, sources, and actions keep unknown properties.** Install stores canonical JSON of the document it accepted. The schemas set `additionalProperties` so those documents still validate.

12. **The checker treats only a non-bool `int` as `integer`.** That matches `type(value) is int` in `create_case`. Draft 2020-12 would also accept `1.0`.

13. **`trusted_origin` is not encoded as a pattern.** It rejects userinfo, fragments, missing paths, and non-loopback HTTP by parsing the URL. The action schema only requires a string URL for `kind: http`.

14. **The deciding rule name is not part of the hashed decision.** `explain` and `Work.explain_admission` return `rule` plus module, symbol, and line. They do not append an event. The public decision and the hashed body stay `{proposal_id, policy_version, status, reason}` plus an optional `phase`. The rule id is written on the side channel (`event_side.rule`, or `Session.side_channel`) and is not an input to `hash`. The file path and line stay inspection-only.

15. **Economic reservations are application state.** `economic.reserve` returns no decision for an action that is not `economic_http` and whose policy has no `economic` block, so non-economic traces stay the same. A committed `economic_http` effect stores `budget_id` and three snapshot digests on `effect_started` only. The budget total lives in `economic_reservations`, which is not part of the hash chain.

16. **`at` has two stored forms.** New events hash an integer microsecond timestamp. The SQLite column is still `REAL`, so the integer is also stored in `at_json` and that text is what verify reads back. Older rows leave `at_json` null and keep the float that was hashed. An integer compared with a fact age or an economic expiry is divided by 1,000,000. A float is already seconds. `due_at` and `expires_at` stay seconds.

17. **The witness process is not a separate OS user.** `WitnessClient` has no seed and opens the log with SQLite `mode=ro`. A process running as the same user can still open that file writable. The witness rechecks hash links; it does not re-run admission.

18. **Candidate records are host claims.** `Session.record_candidate` and `record_evaluation` validate shape, lineage, operators, and budget, and recompute scope from the changed paths they are given. They do not open the Git repository. The Build Thread is the host that computes those fields from Git. In `Work`, a `search` or `operator` credential registers candidates and a separate `evaluator` credential (no automation role, not the registering actor) records evaluations; the application trusts those credentials and does not read Git.

19. **One promotion per thread.** `effect.not_completed` denies a second effect of the promotion action in the same case. The schema does not express that limit.

20. **A local executor's no-write outcome.** `Session.reconcile` for a bound local executor (the Build Thread's Git ref update) records `effect_rejected` with `status: "not_applied"` when it reads the destination under the store lock and the write is absent. No commit can be in flight then, because commit holds the same lock across claim, write, and outcome. The protocol's other no-write codes remain the HTTP 409, 412, and 428. `EffectOutcome` projects the string as `local_status`.

21. **Absent is not proof for a remote destination.** A publishing executor's status may report `absent`. `Session.reconcile` records `not_applied` only when the claim is older than the executor's `settle_seconds`, and `reconciliation_checked` with `absent_within_settle_window` before that. `effect.unresolved` treats an `effect_unknown` followed by that `effect_rejected` as settled. Publishing outputs are `{destination, external_id, url?}`.

22. **Forgetting removes the chain, not the effect.** `Session.forget` deletes a case's events after the policy's `retention` rule allows it. A case that proved an effect leaves a receipt with its head hash and effect ids, which is not itself hash-chained or signed. A receipt shows what the history said when it was deleted; it cannot be re-verified event by event.

23. **A migrant's origin is not verified provenance.** `candidate_registered.origin` names the host and candidate a migrant came from, as read from the shared remote. The receiving host checks the commit against that host's published ref and its own base, but the remote's access control decides who could write that namespace. The origin is provenance for people, not evidence for admission.

24. **Builder coordination is not a v0alpha1 object.** `spec/builder/` describes `sdk.syberlabs.space/builder/v0alpha1`. Those schemas are not checked by the golden-trace validator. A coordination row is not a case event. A selection digest is something a later proposal may cite; it is not itself an admission decision. An integrity `independence_claim` is not evidence. `verified_independence` is set only by the self-report rule, an authenticated human principal, the host mechanism, or a verifier adapter. The SSE tail polls the durable log; that poll is a development transport, not the production wakeup path.

25. **A world binding is not experience, and it is not admission.** Migration `0005` stores an immutable world definition and a host binding from a `candidate_evaluated` event hash to that definition's digest. `instance_equivalence` is `unverified` or `impossible`. It is never `verified`. Selection does not read the binding. There is no trace, no world provider, and no claim that the candidate executed inside the world. `docs/EVALUATION_WORLDS.md` phases 2–5 are not built.

26. **The admission certificate is a separate identity, signed in-process in v0.** `syberlabs certify` writes a DSSE envelope (`payloadType` `application/vnd.syberlabs.admission-certificate+json`, payload `sdk.syberlabs.space/certificate/v0alpha1`, `spec/certificate.schema.json`) over what the thread's journal says about its accepted candidate: base and result commits and trees, contract and policy versions, act class, the host checks admission relied on with their output digests, the promoting actor and approvers, and the chain head and event count at certification. The payload bytes are RFC 8785 JSON (`jcs_bytes`), not `canonical`; nothing hashed in the chain changes. The certificate is not an event, is not in the hash chain, and is not appended to the transparency log; `TransparencyLog.append` accepts only chain-head envelopes. The signing seed is read by the certifying process from the environment variable named in `issuer.seed_env`, so v0 proves possession of that seed plus read access to the journal, not an independent witness; `issuer.signing` says `in-process` for that reason. `syberlabs verify` re-derives commits, trees, changed paths and the diff digest from Git, and the certified prefix of the journal when it is present; it reports the target ref's current state without judging it, and it re-runs no check. A certificate therefore proves what the journal stated at certification, not that `main` took the change. Checks' `output_tail` and the provider's `signal` are deliberately absent.
27. **An intervention's destination is a metric, and its claim is open by design.** The `intervention` executor records the claim-time baseline as a verified `observed` event at the sequence number after `effect_started` and then raises, so `commit` stores `effect_unknown` with error `window_open`; that is the designed state, not a transport failure. `Session.reconcile` settles it unchanged after `window_seconds` (exposed as the executor's `settle_seconds`): `reconciled` when the metric moved as predeclared, `effect_rejected` with `not_applied` when it did not, including a move against the expectation, which the settlement observation records as `moved_against`. A reading that cannot be taken or is older than `max_age_seconds` stays pending. The protocol has no event for an outcome measured after the fact; the two observations carry it. Attribution is not causation.

28. **The in-toto statement is a wrapper around the certificate, not a second certificate.** `syberlabs certify` now writes, by default, a DSSE envelope with `payloadType` `application/vnd.in-toto+json` whose payload is an in-toto Statement v1: `_type` `https://in-toto.io/Statement/v1`, one subject (the thread's target ref, with the result commit and tree as `gitCommit` and `gitTree`), `predicateType` `https://sdk.syberlabs.space/certificate/v0alpha1`, and the unchanged v0 payload of entry 26 as `predicate`. The predicate's RFC 8785 bytes are exactly the bytes the bare form signs; `--bare` still writes that form, under the `payloadType` entry 26 names. The predicate's own `payload_type` field still says `application/vnd.syberlabs.admission-certificate+json`: it is the predicate's identity, not the envelope's. `spec/certificate.schema.json` keeps its `$id` and describes both forms under a top-level `oneOf`. `syberlabs verify` reads both forms and prints the same lines for both. For a statement it checks, in order, `_type` (`statement_type_mismatch`), the four-field set (`payload_shape:<field>`), `predicateType` (`predicate_type_mismatch`), the predicate's shape as before, then that the one subject equals the predicate's `target_ref`, `result.commit` and `result.tree` (`subject_mismatch`); the whole statement must be canonical. The subject is compared with the predicate, not with Git, so a statement whose subject and predicate were forged together passes the signature layer as a re-signed bare certificate does, and the repository layer catches it. A generic DSSE or in-toto verifier with the public key checks the signature over the pre-authentication encoding of `application/vnd.in-toto+json` and reads the statement; it performs neither the repository nor the journal layer, and it trusts the subject. The two forms' signatures are not interchangeable, because each covers its own `payloadType`. Nothing hashed in the chain changes; no event, golden trace or admission rule is touched. Rekor publication and the witness's second `signatures[]` entry are not built.
29. **A self-metric is a reading, not a record.** `GET /metrics/<key>` on the operator service returns a number counted from the store at the time of the read (`Work.metric`), with `observed_at` in epoch seconds and a version that digests key, value and `observed_at`. The version therefore changes on every read even when the value does not; it identifies a reading, not a stored row, and nothing in the store carries it. The ETag is the version in quotes, so an intervention that prefers the `ETag` header records the quoted form as its `external_id`. The counters are projections of the hash-chained events and the obligations table and are not themselves events: `cases_open` applies the same rule as `inspect` (neither cancelled nor complete), the proposal counters count `decision` events by status (`needs_approval` is neither), and every claimed effect is in exactly one of applied (`effect_succeeded` or a verified `reconciled`), not applied (`effect_rejected`) or pending. `uptime_seconds` is the server process's, not the cell's. The route needs the same bearer token as every other read; no schema describes the body.
28. **A critic is a check by name, and its findings are an observation, not an event kind.** The critic-station design names an optional `"kind": "critic"` on a contract check; `evolution.check_evolution` fails closed on unknown check fields and `spec/evolution.schema.json` is frozen `v0alpha1`, so the host identifies a critic by its name instead: `critic` or `critic.<reviewer>` (`syberlabs.critic.is_critic`). The `kind` field waits on a contract-validator packet. The findings document has its own identity, `sdk.syberlabs.space/critic/1` (`spec/finding.schema.json`), and is not validated by the golden-trace validator; what enters the chain is an ordinary `observed` event (key `critic`, source `check:<name>`, `verified: true`, version = the check's `output_digest`) whose value is bounded to 65,536 bytes with `truncated: true` and a `findings_digest` over the critic's full stdout. `critic.no_high_finding` returns no decision unless a required check is a critic, so existing traces are unchanged; independence is checked on the recorded `name@revision` only and the value says `independence: "declared"`.

    *2026-10-20, closed in part.* `spec/evolution.schema.json#/$defs/check` now declares optional `kind`, `command` (default) or `critic`; a check with `kind: "critic"` validates and any other value does not. The runtime is unchanged: `evolution.check_evolution` still refuses the field and `syberlabs.critic.is_critic` still reads the name, which stays authoritative. Reading `kind` as equivalent to the name is the next one-line change in the packet that owns `evolution.py`; until then a contract that sets `kind` validates against the schema and is refused at `start`. The findings document is still outside the golden-trace validator.

30. **The dollar budget and the spend records are outside the frozen `v0alpha1` schemas.** (29 is taken by two pull requests on `main`-based branches; this entry is on the stacked branch.) The governor adds `budget.prices`, `budget.max_dollars` and `budget.strict` to the contract's evolution section, accepted by `evolution.check_evolution` (which still fails closed on any other field), and two host records written only under a priced contract: `candidate_registered.spend` `{dollars, seconds, host_observed}` and `search_finished.spend` `{dollars, seconds, evaluations, candidates, host_observed, unknown_models}`. `spec/evolution.schema.json#/properties/budget`, `spec/candidate.schema.json#/$defs/registered` and `#/$defs/search_finished` are `additionalProperties: false` and do not list them; the files are `v0alpha1`, floor at direction, and were not edited. The schemas are not enforced on contracts at runtime, and `spec/validate.py` checks the examples, the enterprise contract and golden or captured events, none of which price usage, so the 23 golden traces and `validate_events` on every unpriced history are byte-for-byte unchanged. A priced contract and its trace will not validate against the schemas until the contract-validator packet that entry 28 also waits on adds the fields. The stop vocabulary is not extended: a search the host stops for dollars is `stopped: "budget_exhausted"`, the existing enum word, and the dimension is in `spend`. `search_started.budget` keeps its three counted fields; the dollar bound is read from the contract.

31. **Worktree setup is a check by name, and the output cap's default moved.** The frozen `spec/evolution.schema.json#/properties/evaluation` is `additionalProperties: false` with no `setup` field, and `evolution.check_evolution` fails closed on unknown evaluation fields, so the per-worktree setup step (`npm ci` in a fresh checkout with no `node_modules`) is not a contract field: it is a check named `setup` or `install` (`syberlabs.checks.SETUP_NAMES`), as a critic is a check named `critic` (entry 28). `syberlabs.checks.evaluate` runs checks in sorted name order (the stored contract is canonical JSON, so this was already the order; the sort makes it a fact of the code and the docstring no longer says "declaration order"), and when a setup-named check is not `passed` the checks after it are not started and are recorded with the existing vocabulary: `state: "error"`, `exit_code: null`, `duration_ms: 0`, `output_digest` = SHA-256 of zero bytes, `output_tail: "setup_failed"`. No event kind or field is added, so `validate_events` and the 23 golden traces are unchanged. `evolution.DEFAULTS["max_output_bytes"]` is 1,048,576 (the validator's ceiling) instead of 65,536; the value is not written into any recorded body (`search_started.budget` has the three counted fields only), the schema bounds stay 1024 to 1048576, and a contract that declares a cap keeps it. `init` resolves `npm`, `cargo` and `go` to absolute paths at contract-write time and writes nothing for an unresolved tool; the check environment passes the package-cache variables through (`checks.PASS_ENV`, `checks.CACHE_ENV`); a Windows timeout ends the process tree with `taskkill /T /F` and is still recorded `timed_out`. None of this is in a schema: the environment allowance and the kill are host behaviour, and `docs/CRITIC.md` still says the cap is 64 KiB by default, which is now the old value.
    *2026-10-20, closed.* `budget.prices` (per-model rates, the two required and two optional cache rates `economic.PRICE_FIELDS` accepts, each 0 to 1,000,000), `budget.max_dollars` (0 to 1,000,000,000) and `budget.strict` are in `spec/evolution.schema.json`; `candidate_registered.spend` `{dollars: number|null, seconds, host_observed}` and `search_finished.spend` `{dollars, seconds, evaluations, candidates, host_observed, unknown_models}` are in `spec/candidate.schema.json`, each closed to exactly the fields `evolution._spend` writes. All additive: no `required` list and no `additionalProperties: false` moved. `spec/validate.py` checks a priced, critic-bearing contract and a synthetic `search_finished` with `spend` beside the examples, the enterprise contract and, with `--golden`, every golden and captured event; `tests/test_protocol.py` covers both records, a negative price, and the unchanged closure. The schema's `max_dollars` minimum is 0 where the runtime requires a positive amount; the runtime is the stricter and authoritative check.

32. **A thread's start is not one append, so an interrupted start is a state, not a corruption.** (31 is on this stacked branch; 29 and 31 may also be claimed by pull requests based on `main`, so this entry takes 32.) `Kit.start` writes `case_created`, the verified `base` observation and the `sources` attachment as three appends; the protocol has no transaction over several events and no `thread_started` kind, and adding one would change the frozen `v0alpha1` trace. A process that dies between the first and second leaves a well-formed, chain-valid history that `Thread` cannot use. The host treats it as a named state instead of a `TypeError`: `Kit.open` refuses `thread_incomplete`, `Kit.threads` reports `state: "incomplete"`, and `Kit.start` with identical inputs (objective, act class, contract version) on the most recent thread appends the missing records under the same case id. What is not solved: the base recorded on completion is HEAD at completion time, which may differ from HEAD when the interrupted start ran; a death between `base` and `sources` is not detected (the thread opens with the contract's default scope); and the detection reads each thread's history, so `threads` on a journal with many threads loads every one. No event kind or field is added, and the 23 golden traces are unchanged.
    2026-10-20: the inspector's `/api/threads` no longer opens a thread marked `incomplete`; the row carries `status: incomplete`, `candidates: 0`, `chain_valid` from `verify_chain` and a `remedy` line, and `/api/threads/<id>` for it stays 409 `thread_incomplete`. The listing cost noted above is unchanged.

33. **The runner's state is the journal, and "unattended" is an observation.** `syberlabs run` (`build.Runner`) keeps nothing of its own: each pass re-derives the next step of every thread from `candidate_views`, the effect events and the contract, so there is no runner state to lose on a restart and nothing to reconcile between two runners (two passes over the same journal under the file lock take the same step once; the second finds a pending proposal or an evaluated tree and reuses it). The per-thread marker that permits an acceptance without a person is a verified `observed` event with key `unattended`, source and actor `syberlabs.host`, version `"1"`, because `Kit.start` refuses any contract input other than `objective` and `act_class` and a new input is a new contract version; an observation is already in the frozen vocabulary, so no schema and no golden trace changes. What is not solved: the marker is not an admission rule, so a person can still `accept` on an attended thread and a tampered journal is caught by the chain, not by this key; the freshness margin (60 seconds, bounded by half `max_age_seconds`) is a host heuristic read against `time.time()`, so a clock that jumps between the runner's reading and the kernel's can still produce `candidate_evidence_stale`, which the next pass answers with a re-check; and the runner considers only the newest candidate of a thread, so an older acceptable candidate behind a failed one is left to a person.
